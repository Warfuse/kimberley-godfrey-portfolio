# Working on this portfolio

Keep changes focused on a task in `docs/brief.md`. Use `docs/design-system/README.md` as the shared reference and inspect original work before changing a case study. Never invent missing metrics, formulas, client outcomes or delivered screens.

1. Create a branch and describe the problem the change solves.
2. Build and inspect locally with `npm run dev`.
3. Run `npm test`, `npm run check` and `npm run build`.
4. Review keyboard, reduced-motion and responsive behaviour where relevant.
5. Update the affected documentation and describe validation in the pull request.

Use `npm run format` for first-party files. Do not reformat bundled vendor code or modify original artwork to fabricate sharper source evidence. Avoid putting client-sensitive details or API information into issues. Deploy only with explicit owner authorisation and the local production configuration.
